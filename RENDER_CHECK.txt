YOUR /api/health STILL RETURNS OLD SERVER
========================================
{ ok: true, name: "Phantom.wtf" }  without "version":"turso-1.1"
means Render is NOT running the new server.js yet.

Fix in order:

1) GitHub
   - Open the repo connected to Render
   - Confirm server.js contains the text:  version: 'turso-1.1'
   - Confirm package.json has:  "@libsql/client"
   - If not, upload/replace from PhantomAuth.zip → server/
   - Commit + push to main/master

2) Render → phantomauth service → Settings
   - Root Directory:  must be the folder that CONTAINS server.js
     examples:  server   OR  PhantomAuth/server  OR  empty if server.js is repo root
   - Build Command:   npm install
   - Start Command:   node server.js
   - Instance: free

3) Render → Environment (must exist)
   TURSO_DATABASE_URL = libsql://....turso.io
   TURSO_AUTH_TOKEN   = ...

4) Render → Manual Deploy → Clear build cache & deploy

5) Wait until deploy status = Live

6) Open again:
   https://phantomauth-khc4.onrender.com/api/health

GOOD response looks like:
{
  "ok": true,
  "name": "Phantom.wtf",
  "version": "turso-1.1",
  "turso": true,
  "hasToken": true,
  "t": 1234567890
}

- version turso-1.1  = new code is live
- turso true         = URL env is set
- hasToken true      = token env is set

If version is missing → still old code (fix root directory / push)
If turso false → env vars missing or wrong names
If deploy fails → open Logs, look for npm errors
